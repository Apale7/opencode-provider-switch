# Auto Alias 所有权与兼容基线

> 基线：2026-07-21 当前工作区源码。本文冻结 manual、auto、locked、upgraded 与历史混合数据的保守所有权规则。

## 所有权分类

父级保护优先于 target provenance：

| Alias.AutoGenerated | Alias.Locked | Target.AutoGenerated | 有效所有权 | 自动维护权限 |
|---|---|---|---|---|
| false | 任意 | 任意 | manual/user-owned | 不得自动增删、改序或翻转标志 |
| true | true | 任意 | protected snapshot | 不得自动修改 Alias 或 target |
| true | false | true | system-owned target | 可按可信 reconcile 添加、删除和排序 |
| true | false | false/缺失 | unknown/protected target | 不得自动删除、替换、改序或转 ownership |

- manual alias 内残留 auto target 仍整体按 manual 保护。
- locked auto alias 的 target 全部受保护；target 标志只保留来源信息。
- unlocked auto alias 含 protected target 时为 historical mixed；只可维护明确 system-owned target。
- 重复 alias 名、重复 target identity 或冲突标志为 ambiguous，破坏性动作默认阻断。
- 不得通过 alias/model 同名、目录命中或字段缺失反推系统所有权。

规范状态：canonical manual 为 alias/targets 全 false；canonical unlocked auto 为 alias true/unlocked 且 targets 全 true；locked auto 为受保护快照；Upgrade 后为 canonical manual；其他组合均按 historical mixed 保守处理。

## 当前风险

- Bind 使用只查 manual 的 `FindAlias` 判断存在性，同名 auto alias 可能被新 manual alias 整体替换并丢 target。
- 普通编辑 locked auto alias 可能静默转 manual，却残留 target auto 标志。
- unbind/reorder 底层可先修改 auto alias，随后调用方用 manual-only lookup 返回 not found，形成已保存但报错。
- `RemoveProviderAutoTargets` 只看 alias-level auto/unlocked，会删除该 Provider 的全部 target，不检查 `Target.AutoGenerated`。
- 当前 Provider 删除没有预检受保护引用，也不清本次持久化的 Priority：会先删除 Provider，再调用上述 alias-level cleanup 并 Save；manual/locked target 可悬空，mixed protected target 可误删，随后 reload 可能失败并形成磁盘/runtime 分裂。
- Load/priority/auto generation 可能重排 mixed alias，改变受保护 target 的路由顺序。
- discovery error/empty 会保留旧目录，但持久化 `ModelsSource=discovered` 不能证明本次观察可信。
- 当前同连接 discovery error/empty 后仍可能基于保留的旧 discovered 目录调用 auto alias 生成，产生新增或重排；这是待修复缺陷，目标契约要求零 Alias diff。
- Protocol 未完整进入连接等价判断，旧目录可能被错误信任。
- 当前 duplicate/ambiguous Alias 的多数 mutation 按首个匹配项操作，并未统一阻断；保守阻断是待实现门禁。

## 人工修改门禁

| 操作 | Manual | 任意 auto/locked |
|---|---|---|
| 编辑 Alias | 允许 | 拒绝并要求 Upgrade |
| bind/toggle/unbind/reorder target | 允许 | 拒绝并保证零变化 |
| 删除 Alias | 经影响 preview 后允许 | 经影响 preview 后允许，不构成 ownership 转换 |
| Upgrade | no-op/stable error | unlocked 与 locked auto 均允许 |

所有入口必须先按名称查找任意类型 Alias，再判所有权；不得用 manual-only lookup 的 nil 推断不存在。拒绝必须发生在内存变更、Save 与 reload 之前。

## Upgrade 契约

Upgrade 是普通管理入口唯一允许的 auto-to-manual 转换：

- 前置条件：Alias 存在且 `AutoGenerated=true`，locked 同样可 Upgrade。
- 同一候选事务内设置 Alias `AutoGenerated=false`、`Locked=false`，全部 target `AutoGenerated=false`。
- 名称、DisplayName、Protocol、Enabled、target identity、顺序及 Enabled 原样保留。
- 不持久化中间 ownership 状态；重复执行幂等。
- Upgrade 后 discovery、Priority 与 Provider auto cleanup 不得再修改该 Alias。

## 模型发现与 reconcile

可信非空发现必须是针对当前 Provider 指纹完成的成功、完整、规范化后非空结果。指纹至少覆盖 Protocol、规范化 BaseURLs、strategy、凭据集合和 Headers；敏感值只参与内部摘要。

当前发现实现遇到任意 BaseURL/API key 组合的首个非空结果即返回，不能证明该目录覆盖其他端点或凭据。因此它只能支持非破坏性新增与交互提示，不能触发减集 prune。允许破坏性减集前必须新增并冻结“完整观察”机制，例如对所有有效组合聚合并明确集合语义，或由上游提供权威完整目录标记；无法证明完整时一律按 stale/untrusted 处理。

| 结果 | Provider.Models | Auto Alias |
|---|---|---|
| skip/未执行 | 保留；连接变化时标 stale | 零变化 |
| error | 保留最后目录并标 stale | 零变化 |
| 成功但空 | 保留最后目录并标 stale | 零变化 |
| 成功、完整、非空 | 更新目录 | 开关开启时 ownership-aware reconcile |
| imported/manual/来源未知 | 可展示 | 不用于破坏性 prune |

只有满足上述完整观察条件后，才可执行以下可信 reconcile 规则：

1. 只处理该 Provider 在 unlocked auto alias 中 `Target.AutoGenerated=true` 的 target。
2. 模型不在新集合或协议不再兼容时，才可删除 system target。
3. manual、locked、unknown target 始终保留。
4. 只有本次实际删除系统 target 后变空的纯 auto alias 可删除；不得顺带删原本为空的其他 Alias。
5. 同名 manual/locked Alias 保留并报告 collision；不得覆盖。
6. pure auto 可按 Priority 排序并保留 target Enabled；mixed 既有顺序完全保留，新系统 target 只能追加。
7. 不修改 Alias DisplayName/Enabled/Locked/Protocol 或现存 target ownership。
8. 相同输入重复执行产生空 diff。

`ModelsSource=discovered` 只表示来源，不足以证明本次结果可信。当前 bind 仅凭该字段和非空旧目录硬拒绝未知模型，在 discovery error/empty 或漏判 Protocol 变化时可能错误阻止合法外部模型；目标实现必须让 bind 使用本次可信度/指纹，目录 stale/untrusted 时只提示。`Target.Model` 继续是外部符号；上述减集只是系统 provenance reconcile，不是建立本地模型外键。

## Protocol、Disabled 与删除

- Protocol 属于发现指纹。变化且 discovery error/empty 时保留目录和 targets，诊断 stale/protocol mismatch；可信非空时只迁移纯系统内容。
- pure auto alias 因系统 target 删除变空时可按新协议重建；含 protected target 时不得原地改 Alias.Protocol。
- Provider disabled 只改变可用性，必须产生零 Alias diff；重新启用后引用可恢复。
- 全局或 Provider auto switch 关闭只暂停生成/prune/排序，不删除数据或改 ownership。
- 目标契约要求 Provider 删除可自动清明确 system target 和 Priority，也可从多值 Rewrite Provider selector 中移除目标 ID，但移除后必须仍非空、只能收窄匹配范围；singleton selector 不得清成 empty=all。manual、locked、mixed protected target 默认阻断，并提供 rebind/remove/delete 等显式动作。当前实现不满足该契约：它无预检、按 alias-level 清理并可能在 Save 后 reload 失败。
- 删除清理不受当前 auto switch 影响；依据只来自持久化 ownership。
- 当前 `RemoveProviderAutoTargets` 应由 ownership-aware planner 取代。

## 旧配置兼容

- 缺 ownership 字段按 Go 零值读取为 manual/unknown，不自动追认为 auto。
- manual+auto target 按 manual 保护；auto+manual target 按 mixed 处理。
- `AutoGenerated=false, Locked=true` 按 manual/protected 保留，仅显式计划可规范化。
- locked auto 必须可读、可路由、可 Upgrade。
- duplicate/ambiguous fixture 的目标门禁是阻断相关 mutation，不由“第一个匹配项”决定；当前多数操作仍按首个匹配项处理，必须修复。
- Load 与普通 Save 不得对 mixed/ambiguous Alias 自动改序、删项或翻转标志。
- 缺失全局 `auto_alias_enabled` 继续默认 true；Provider nil override 保持现有默认，但不得回填历史 ownership。

## 禁止的隐式转换

- bind 覆盖同名 auto alias。
- locked auto 因普通编辑变 manual。
- auto unbind/reorder 先保存再报 not found。
- 仅因父 Alias 为 auto 删除 protected target。
- 因目录命中把 manual/unknown target 标 auto。
- 除 Upgrade/显式 repair 外翻转 ownership。
- discovery error/empty、disabled、Load、启动或通用 Save 触发 prune。
- Protocol 变化后继续信任旧 discovered 目录。
- Priority 重排 mixed/locked/manual Alias。
- 自动清理无关空 Alias。

## 可测试不变量

- 所有 ownership 组合按矩阵分类，Load/Save round-trip 不改变结果。
- 对 auto alias 的 edit/bind/toggle/unbind/reorder 被拒绝时，候选、磁盘与 runtime 均不变。
- Upgrade 前后除 ownership 标志外逐字段相等。
- 目标行为中 discovery error/empty/skip 的 Alias diff 为空；先添加回归测试证明当前缺陷，再修复。
- 可信减集只删 eligible system target；protected target 逐字段不变。
- mixed alias 在 discovery、Priority 与 Load 后既有顺序不变。
- Protocol 变化加 error/empty 保留；可信非空只迁移纯系统项。
- disable/enable 不改变 Alias；Provider 删除默认阻断 protected 引用。
- manual Target.Model 不在目录仍可通过结构校验。
- reconcile/delete plan 重复执行幂等。
- 旧字段缺失、manual+auto、auto+manual、locked、duplicate 均有 fixture。
- 所有客户端入口对同一 ownership 状态返回等价结果。
