## steps

> 步骤之间存在依赖关系，只能顺序执行。每个 step 内部的 tasks 之间无依赖，由多个子代理并行完成。

### - [x] Step 1：冻结产品语义与数据契约

- 依赖：无
- 完成定义：形成并确认一个无歧义契约：alias 名称只要匹配任一 Provider Group 的模型 ID，就属于“自动模型 alias”；用户对它的排序、启停、规则和可选自定义 target 都是覆盖层，不再把 alias 升级为手动；手动 alias 仅用于当前所有 Provider Group 模型目录都不包含该名称的自定义名称。
- Tasks（并行，子代理执行）：
  - [x] Task 1.1：梳理并固化 alias 拥有权判定：以 `(protocol, aliasName)` 与 Provider Group `models` 的精确模型 ID 匹配为主；在当前存储仍只以 `alias` 字符串唯一时，跨协议同名模型先以诊断/警告处理，不在本方案内引入同名多协议 alias 存储重构。
  - [x] Task 1.2：固化配置字段方案：保留 `Alias.AutoGenerated` 表示模型目录 alias；保留 `Target.AutoGenerated` 区分系统发现 target 与用户自定义 target；新增或等价实现 `Alias.TargetOrderMode`，取值为空/`provider_priority` 表示自动按 Provider Priority 排序，`custom` 表示用户已拖拽排序且后续 Provider Priority 变化不得重排既有 target。
  - [x] Task 1.3：固化新 target 合并排序规则：默认 `provider_priority` 模式下，所有 target 按 Provider Priority 排序；`custom` 模式下，保留现有 target 顺序，新发现的系统 target 自动加入到列表尾部，并且同一批新增 target 之间仍按 Provider Priority、Group ID、Model 稳定排序；提供“重置为 Provider 顺序”操作把模式改回 `provider_priority`。
  - [x] Task 1.4：固化旧配置迁移规则：旧手动 alias 若名称已匹配模型目录，不再阻止自动加入；在下一次相关配置写入时转换为自动模型 alias，并保留 display name、enabled 状态、既有 target 顺序和 target enabled 状态；既有非系统 target 标记为用户自定义 target，不被自动清理。
  - [x] Task 1.5：固化全局/Provider 自动 alias 开关语义：开关只控制“新增系统 target/alias 的自动维护”，不再作为 proxy 运行时查找已存在自动 alias 的路由门禁；若用户要停止路由，应禁用 alias 或禁用 target。

### - [x] Step 2：改造 Config 与路由解析核心

- 依赖：Step 1
- 完成定义：Config 层可以在不丢失用户覆盖的前提下持续同步模型目录 alias；proxy 对手动/自动 alias 使用单一路径解析，不再需要“手动优先、自动 fallback、升级后失去自动维护”的分叉。
- Tasks（并行，子代理执行）：
  - [x] Task 2.1：在 `internal/config/config.go` 增加 alias 目录匹配与归一化 helper，例如 `AliasNameMatchesProviderModel(name, protocol string) bool`、`NormalizeCatalogAliasOwnership()`、`ensureAutoAliasForTargetLocked(provider, group, model)`；所有 helper 必须使用精确 `(provider, group, model)`，不得回退到 default/兄弟 Group。
  - [x] Task 2.2：重写 `AutoGenerateAliases`：当 alias 名称匹配模型目录时创建或维护 `AutoGenerated=true` alias；如果已有同名手动 alias，按 Step 1 的迁移规则转为自动模型 alias 并保留用户覆盖；新增系统 target 不覆盖已有 target 的 enabled、AutoGenerated=false 状态或 custom 顺序。
  - [x] Task 2.3：重写 target 排序 helper：`SetProviderPriority` 只重排 `TargetOrderMode=provider_priority` 的自动模型 alias；`TargetOrderMode=custom` 的 alias 保持用户顺序；新增系统 target 使用 Step 1 的尾部合并规则；`ReconcileProviderGroupAutoTargets` 只移除 stale 的 `Target.AutoGenerated=true` target。
  - [x] Task 2.4：调整 alias 查找 API：提供单一 `FindAlias(name)` 或等价方法返回唯一 alias（无论自动/手动），仅用 `AutoGenerated` 做显示和维护策略；proxy 不再因 `AutoAliasEnabled=false` 跳过已存在自动 alias；未命中 alias 仍返回 model-not-found，不引入 direct provider/group fallback。
  - [x] Task 2.5：补充 Config 单元测试：覆盖默认 Provider Priority 排序、自定义顺序后新增 target 追加到尾部、Provider Priority 变化不改 custom 顺序、重置排序恢复 Provider Priority、禁用 target 后刷新模型不重新启用、stale 系统 target 被清理而用户自定义 target 被保留。

### - [x] Step 3：改造 Service、Lifecycle、管理 API 与入口适配

- 依赖：Step 2
- 完成定义：所有管理入口都允许在自动模型 alias 上执行“安全覆盖”操作；不再要求先 `UpgradeAutoAlias`；仍然阻止会破坏模型目录语义或制造重复同名 alias 的操作。
- Tasks（并行，子代理执行）：
  - [x] Task 3.1：替换 `lifecycle.RequireManualAliasMutation` 的调用点：`SetAliasTargetDisabled`、`ReorderAliasTargets`、rewrite rule 关联等覆盖操作允许自动模型 alias；真正创建/重命名手动 alias 时才要求名称不匹配任何 Provider Group 模型目录。
  - [x] Task 3.2：调整 `UpsertAlias`：当输入 alias 名称匹配模型目录时，行为变为编辑自动模型 alias 的 display name、enabled 等元数据，禁止把 protocol 改成不匹配目录协议；当名称不匹配模型目录时，按手动 alias 创建/编辑。
  - [x] Task 3.3：调整 target 绑定/解绑语义：自动模型 alias 上的系统 target 不能通过“解绑”永久删除，解绑请求应被解释为禁用或返回明确错误并提示使用禁用；用户自定义 target 可移除；如允许在自动模型 alias 上添加自定义 target，必须标记 `AutoGenerated=false` 且参与用户覆盖顺序。
  - [x] Task 3.4：废弃 `UpgradeAutoAlias` 产品路径：保留后端兼容接口但返回 no-op/已废弃提示或转为“保留自动维护的覆盖编辑”；前端、TUI、CLI 不再展示“升级为手动”作为编辑前置动作。
  - [x] Task 3.5：更新 HTTP WebAdmin、Wails desktop bindings、TUI/CLI 调用与错误码：冲突错误应明确说明“该名称是模型目录 alias，请编辑自动 alias 或使用其他手动 alias 名称”；所有新增/变更错误信息应便于 i18n 展示。
  - [x] Task 3.6：补充 Service/Lifecycle/API 测试：覆盖自动 alias 可禁用 target、可拖拽排序、可编辑元数据、不可创建同名手动 alias、旧手动同名 alias 被目录维护吸收、全局自动维护关闭后已存在 alias 仍可路由。

### - [x] Step 4：改造 UI/UX 与 i18n

- 依赖：Step 3
- 完成定义：用户在 GUI/Web/TUI/CLI 中看到的是“自动模型 alias + 可编辑覆盖”模型；不会再遇到“必须升级为手动后才能调整，但升级后失去自动加入和 Provider 顺序”的矛盾。
- Tasks（并行，子代理执行）：
  - [x] Task 4.1：更新 `frontend/src/App.tsx` alias 列表与详情：自动模型 alias 显示“Auto model alias/自动模型别名”，手动 alias 显示“Custom alias/自定义别名”；移除“Upgrade to Manual/升级为手动”主按钮；新增说明“新的匹配 Provider Group target 会自动加入”。
  - [x] Task 4.2：更新 target 列表交互：自动模型 alias 允许拖拽排序、启用/禁用 target；系统 target 的删除按钮隐藏或替换为禁用；用户拖拽后显示“Custom order/自定义顺序”徽标，并提供“Reset to provider order/重置为 Provider 顺序”。
  - [x] Task 4.3：更新手动 alias 创建表单：输入名称若匹配已知 Provider Group 模型目录，提示该名称会由自动模型 alias 管理，并引导打开现有自动 alias；不允许创建同名手动 alias 来 shadow 自动 alias。
  - [x] Task 4.4：更新请求 rewrite rule 体验：允许规则关联自动模型 alias；Provider Group selector 继续使用精确 `(provider, group)`；新增规则文案说明新增 target 对 wildcard 规则的影响，避免用户误以为新增 Provider 不会参与规则。
  - [x] Task 4.5：同步前端类型和 Wails 生成模型：`AliasView` 暴露 order mode、是否模型目录匹配、target 是否系统生成/用户自定义等必要字段；保持旧字段兼容，避免已有页面空值崩溃。
  - [x] Task 4.6：补齐 `frontend/src/i18n/locales/en.json` 与 `zh-CN.json`：新增自动模型别名、自定义别名、自定义顺序、重置 Provider 顺序、模型名冲突、系统 target 不能删除、自动维护关闭只影响新增同步等文案。
